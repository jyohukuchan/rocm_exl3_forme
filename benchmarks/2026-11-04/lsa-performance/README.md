# 通常attention / LSAの速度・長文比較

> **旧実装の測定記録です。** Treeがdecodeでも階層探索を行い、LSAのdecode graphが未対応だった版を測っています。[修正後の限定比較](../../2026-11-05/lsa-decode-fix/README.md)を併せて参照してください。

EXL3 Qwen3.8-27B、K5/V4、batch 1、chunk 4096、64 token固定生成。GPU power modeはauto。

各長さ1回のwarmup後、2回の中央値。通常比は大きいほど高速。小さい差は測定・入力間のばらつきと合わせて判断する。

## この測定での判断

- **R9700×1:** 8K〜64Kは通常attentionが入力処理・生成とも速い。128Kの生成は通常とFlatが約14.8 token/sで同等だが、入力処理は通常が速い。約256KではFlatが入力処理1.09倍、生成1.34倍となり、64 tokenの応答完了も370.8秒から340.2秒へ短縮した。
- **V620×1:** 8Kは通常attentionが速い。32KではFlatの生成が1.30倍でも、64 tokenの応答完了は通常175.2秒、Flat202.3秒で通常が速い。64KではFlatの入力処理はほぼ同等、生成は1.76倍、応答完了は421.5秒から412.6秒となった。生成速度の倍率を応答全体の倍率と区別して選ぶ。
- **Tree:** 今回の全条件で通常attentionより遅い。約256Kの生成は通常9.71、Flat13.01、Tree1.11 token/sであり、現行移植版では速度目的の選択肢として勧めにくい。
- **長文での取得:** ウォームアップを含む72/72ケースで番号取得に成功し、回答先頭の最有力tokenも通常attentionと一致した。個々のケースの先頭KLの最大値は0.000295 nats。これは3配置の合成番号検索と1回答位置の比較であり、一般的な長文品質が同等であることまでは示さない。

この結果はEXL3 3.05 bpw/head 6 bit、K5/V4、batch 1での現行実装の測定。
LSAを適用する16層以外のGated DeltaNet 48層やMLPも含み、通常attentionの既存graph最適化も有効。
V620は8K〜64K、R9700は標準RoPEで約256Kまで測定した。

## 範囲と注意点

番号取得は合成文書の限られた配置だけを評価している。KLも最初の回答位置の値であり、RULER全体の精度や文書全体のperplexityではない。

生成速度にはindex・階層の更新も含む。固定64 tokenの平均を定常的な単一token速度と同一視しない。約256Kの追加測定ではtoken間隔も元JSONに保存している。

LSAは保存するKVを削減しない。indexと作業領域を追加するため、メモリ削減策としては評価しない。ピークは各リクエスト中のPyTorch割当最大値を、本測定間で中央値にしたもの。

測定中にTreeの管理キーハッシュ、選択処理のソート作業領域、LSAのdense prefixのKV展開範囲を修正した。通常attentionの完走データは保持し、Flat/Treeは最終修正後に全長さを再測定した。各方式のcommit・ハーネスSHA256・再開履歴を元JSONに残している。
